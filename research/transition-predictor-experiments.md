# Експерименти з TransitionPredictor

## 1. Мета

Дослідити ефективність алгоритму прогнозування наступної сторінки на основі історії переходів між URL.

На відміну від базового `MostFrequentPredictor`, цей алгоритм враховує не загальну популярність сторінок, а залежність наступної сторінки від поточної.

## 2. Принцип роботи

`TransitionPredictor` аналізує історію навігації та визначає, які сторінки найчастіше відкривалися після поточної сторінки.

Для цього алгоритм:

1. Переглядає всі події навігації.
2. Відбирає події, у яких `PreviousUrl` відповідає поточному URL.
3. Підраховує кількість переходів на кожну наступну сторінку.
4. Виключає поточну сторінку з результатів.
5. Сортує сторінки за спаданням кількості переходів.
6. Повертає не більше `maxResults` результатів.

Оцінка сторінки (`Score`) дорівнює кількості зафіксованих переходів на неї з поточної сторінки.

## 3. Експеримент 1: визначення найчастіших переходів

Вхідна історія переходів:

- A → B
- A → C
- A → B
- A → D
- A → B
- A → C

Поточна сторінка: A.

Очікувані результати:

| Сторінка | Кількість переходів |
|---|---:|
| B | 3 |
| C | 2 |
| D | 1 |

Критерій успіху: алгоритм повертає сторінки в порядку спадання кількості переходів із поточної сторінки.

## 4. Експеримент 2: виключення нерелевантних переходів

Вхідна історія:

- A → B
- A → C
- B → D
- C → D
- B → E

Поточна сторінка: A.

Очікуваний результат:

| Сторінка | Кількість переходів |
|---|---:|
| B | 1 |
| C | 1 |

Критерій успіху: алгоритм враховує лише переходи, у яких попередньою сторінкою була A. Переходи з B та C не повинні впливати на прогноз.

## 5. Експеримент 3: обмеження кількості результатів

Вхідна історія:

- A → B
- A → B
- A → B
- A → C
- A → C
- A → D

Поточна сторінка: A.

Максимальна кількість результатів: 2.

Очікувані результати:

1. B — 3 переходи.
2. C — 2 переходи.

Критерій успіху: алгоритм повертає рівно два результати у правильному порядку.

## 6. Експеримент 4: відсутність відомих переходів

Вхідна історія:

- A → B
- B → C
- C → D

Поточна сторінка: X.

Очікуваний результат: порожній список прогнозів.

Критерій успіху: якщо в історії немає переходів із поточної сторінки, алгоритм не повинен повертати випадкові або нерелевантні результати.

## 7. Обмеження

Алгоритм враховує частоту переходів із конкретної сторінки, але не аналізує повний контекст поведінки користувача.

Основні обмеження:

- Не враховує часову давність переходів.
- Не розрізняє різні сесії користувача.
- Не аналізує послідовності з кількох попередніх сторінок.
- Для сторінок без історії переходів не може самостійно сформувати прогноз.
- Оцінка `Score` відображає абсолютну кількість переходів, а не ймовірність переходу.

Також часті переходи в минулому не гарантують, що користувач повторить їх у майбутньому.

## 8. Наступний етап дослідження

Інтегрувати `TransitionPredictor` у браузер Cachd та перевірити його роботу на реальній історії навігації.

Після цього провести порівняльне дослідження з `MostFrequentPredictor`, використовуючи однакові тестові набори та метрику Hit@K.

Мета порівняння — визначити, наскільки врахування переходів між сторінками покращує точність прогнозування наступної навігації.
